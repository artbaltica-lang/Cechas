# Как восстановить базу Cechas

Исходный SQL лежит в `supabase/migrations/20261013190000_init.sql`. Это первая и пока единственная миграция. Она создаёт `profiles`, `jobs`, `topics`, `replies`, связи, ограничения и правила доступа из `docs/mvp.md`.

Пароль в этих таблицах не создаётся. Ключ `service_role` в репозиторий и в приложение React не кладётся.

## Новая среда

1. Создайте пустой проект Supabase.
2. Откройте SQL Editor.
3. Вставьте содержимое `supabase/migrations/20261013190000_init.sql` целиком и выполните его один раз.
4. В настройках проекта скопируйте Project URL и anon public key.
5. В корне сайта скопируйте `.env.example` в `.env` и вставьте туда эти два значения.

Файл `.env` уже указан в `.gitignore`. В GitHub попадает только `.env.example` с примерами, не с настоящими ключами.

Повторно выполнять эту миграцию на той же базе не нужно: `create table` остановится, потому что таблицы уже есть.

## Регистрация после восстановления

Имя передаётся при создании входа, отдельная вставка в `profiles` не нужна:

```js
supabase.auth.signUp({
  email,
  password,
  options: { data: { name } }
})
```

Удаление своей учётной записи вызывает `delete_own_account()`. Вместе с ней уходят профиль, объявления, темы и ответы.
